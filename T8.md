# T8: Not matched — check these

The issue panel and read-only evidence context now end with a separate,
initially collapsed **Not matched — check these** section. Each card contains
the issue link, stored original part and failure-mode strings, recorded closure
date (if any), and exactly one reason. Hints have no decision controls and never
enter `strong` or `relatedRevision`, recurrence counts, or decision eligibility.

## Selection and search bounds

Selection is deterministic, at most three unique CAPAs, in this priority order:

1. **Part number differs only slightly**: same normalized failure mode, closed
   1–365 UTC calendar days before detection, different parsed base, and compacted
   identifiers equal or one insertion/deletion/substitution/adjacent transposition
   apart. Compaction uppercases and removes whitespace and hyphens only.
2. **No closed date recorded**: same normalized full part and failure mode, with
   `closedDate` absent, null or empty. Invalid nonempty dates do not qualify.
3. **Older precedent**: same normalized full part and failure mode, closed more
   than 365 days before detection.

Within dated categories, closure date sorts newest first, then issue key and ID.
Missing-date hints sort by key and ID. Revision differences are never hints.
Existing match logic and its date window have not changed.

There are three candidate searches, each capped at one page of 50 results:
normal-window CAPAs; same-part CAPAs without a date clause; and same-part older
CAPAs, newest closure first. At most 150 unique candidates are freshly fetched,
five at a time. Duplicate and current issue IDs are skipped. The displayed hints
are a bounded selection, not an exhaustive inventory. The dev harness uses the
whole supplied corpus with the same selection function, without Jira search caps.

Every search and candidate read uses `asUser()`. A fresh candidate 403/404 drops
that record without parsing its body. A current-property/search 403/404 returns
nothing. Search totals and stale issue properties are never exposed or used.
Hint lookup errors leave match classification and decision eligibility intact.

## Forge documentation verification

Forge MCP verified POST `/rest/api/3/search/jql`, GET
`/rest/api/3/issue/{issueIdOrKey}` (including issue properties), and the existing
`read:jira-work` scope. UI Kit references verified Button, Box, Stack, Text and
Link, including relative issue links and the selected toggle state.

The [entity-property documentation](https://developer.atlassian.com/platform/forge/manifest-reference/modules/jira-entity-property/)
documents date comparisons and ordering but does not establish that
`qlClosed IS EMPTY` works for this alias. Focused Forge MCP documentation searches
did not verify support; this is not a claim that a live tenant rejected it.
The implementation avoids relying on that operator: the capped same-part query
has no date condition, and the pure selector checks the fresh stored property.
Live alias/index visibility and native rendering remain owner checks.
