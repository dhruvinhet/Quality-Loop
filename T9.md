# T9 — UX polish

The issue panel now offers a clear setup choice, progress copy, recovery actions,
and a read-only notice. Evidence uses the requested terminology, help sentence,
date format and field order. The admin page explains the existing sample workflow
in three steps and links to sample NCs the current viewer can browse.

## Files changed

- `src/frontend/index.jsx`: NC/CAPA setup choices; loading copy; remember a saved
  record so evidence appears immediately after its first save.
- `src/frontend/CaptureForm.jsx`: preselect the setup type without writing until
  Save; saving and saved next-step copy; explicit ISO date display, placeholders
  and calendar buttons.
- `src/frontend/ReadOnlyCapture.jsx`: read-only notice and next step, including
  issues with no saved record.
- `src/frontend/MatchView.jsx`: visible search progress, plain search error with
  Retry, and decision/hint loading errors that do not discard available evidence.
- `src/frontend/EvidenceResults.jsx`: exact requested help and no-match copy;
  separate explanation for related revisions; signature, closure with elapsed
  days, evidence, root cause, actions, then supporting facts. Issue key/title
  remain the card header. No evidence or matching classifications changed.
- `src/frontend/DecisionDetails.jsx`, `src/lib/decisions.js`,
  `src/frontend/ConcurrencyCheck.jsx`: consistent decision labels in controls,
  state, history and developer-check copy; history dates display as YYYY-MM-DD.
  Decision eligibility, transitions and storage behavior are unchanged.
- `src/frontend/issueContext.jsx`: explain the read-only evidence view and where
  to record a decision.
- `src/frontend/GettingStarted.jsx`, `src/frontend/adminPage.jsx`: three-step
  checklist, sample NC links, loading/empty/error copy and refresh/retry.
- `src/resolvers/admin.js`: read-only, paginated checklist link lookup against
  existing `sample:` registrations. Recheck Jira admin permission on every page,
  read the current registration, and fetch each registered NC `asUser()` before
  showing its fresh key. Skip 403/404 without parsing the response. Require the
  registered ID, sample label, project and NC record type to still agree. This
  lookup does not create sample issues or write storage/Jira data.
- `src/resolvers/__tests__/admin.test.js`: verify link lookup pagination,
  permissions, denied reads, stale registrations, changed labels/project/type,
  and payload validation.
- `T9.md`: validation, screen descriptions and owner checks.

No manifest, app ID, scopes, egress, triggers or dependencies changed. Matching
and hint selectors/JQL remain byte-for-byte unchanged. No `eval/test/` files
were opened or modified. Git, deployment and installation were not run.

## Exact click/check sequence

1. On an issue without QualityLoop details, open **qualityloop**. Capture the
   setup screen. Click **Set up as NC**; check NC is preselected. Reload without
   saving and check setup still appears. Repeat with **Set up as CAPA** and
   check closure/evidence fields appear. Dates must display YYYY-MM-DD.
2. Enter valid NC details and click **Save**. Check visible saving copy, then
   searching copy, then evidence without reopening. With a unique part such as
   `T9-NO-MATCH-20261101` and a valid detected date, check the exact no-match
   sentence and next step. On a network failure during search, check the plain
   message and **Retry**; restore connectivity and click **Retry** to recover.
3. Open **Jira settings → Apps → QualityLoop data**. Capture the three-step
   checklist above maintenance. With no browsable sample NC, check the empty
   guidance. Go to a test **project → QualityLoop → Create sample scenario
   (5 issues)**. Review the listed writes before confirming. Wait for sample
   readiness. This uses the existing sample feature; T9 creates nothing on load.
4. Return to **QualityLoop data**, click **Refresh sample links**, then **Open
   sample NC [key]**. Open **qualityloop**. Check DEMO CAPA-B's card: signature,
   closure YYYY-MM-DD and **45 days after closure**, **No effectiveness evidence
   recorded at closure**, root cause, actions, supporting facts. Check the exact
   help sentence directly beneath **Possible recurrence evidence**.
5. On that test NC, choose **Engineer-confirmed recurrence**, enter a reason and
   evidence, and click **Record decision**. Check state/history labels and the
   YYYY-MM-DD history date. Repeat **Not a recurrence** (with category) and
   **Effectiveness concern**. For concern, choose **Keep decision only** in the
   separate follow-up confirmation unless a task write is intentionally wanted.
6. Test the issue as a viewer with Browse but without Edit Issues: capture the
   read-only notice, check evidence is visible and no form/decision controls
   appear. Open **QualityLoop evidence** and check its read-only-view notice.
7. As an admin who cannot browse the sample NC, refresh sample links: its key
   must not appear. Restore access and refresh to check the link returns. After
   removing a sample through the existing confirmed removal flow, refresh links
   and check it disappears. A very recent registration may need another refresh
   because KVS queries are eventually consistent.
