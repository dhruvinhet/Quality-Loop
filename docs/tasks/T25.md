# T25 — QL-006 and QL-029: shared evidence URL validation

Read `AGENTS.md`, review §1.3 and the QL-006 / QL-029 sections first. The owner's
HTTPS-only decision takes precedence over the review's optional HTTP policy.
T23 and T24 remain in place; no later review task is included.

## Policy and files changed

- `src/lib/urls.js`: the single `validEvidenceUrl()` implementation. New values
  require an explicit HTTPS scheme, a nonempty hostname, no credentials, no
  surrounding or internal whitespace, no control characters, and at most 2000
  characters. It also rejects backslashes, empty authorities and implicit URL
  repairs such as `https:///report`. The default always rejects HTTP.
  The explicit `{ allowHttp: true }` option is used only to recognise syntactically
  safe legacy HTTP for warning/plain-text display; write validation never uses it.
- `src/lib/capture.js`: uses the shared validator for nonempty CAPA evidence.
  Invalid URLs, including HTTP, produce the exact field message
  **Use an https:// link.** Empty optional evidence is still permitted; whitespace
  alone is invalid. Existing non-string text validation remains in place.
- `src/lib/decisions.js`: replaces its local validator with the shared function.
  Invalid decision URLs receive **Use an https:// link.** The maximum of five
  links and 2000 characters per URL is preserved. Decision states and concern
  eligibility are unchanged; invalid evidence is not silently treated as absent.
- `src/frontend/EvidenceLink.jsx`: shared rendering using `validEvidenceUrl()`.
  Valid HTTPS produces a Link with the original URL. Valid legacy HTTP produces
  the original URL as plain text and **Not a secure link (http)**, with no Link.
  All other stored values produce **Invalid evidence link**, with no Link and no
  echo of potentially credentialed input.
- `src/frontend/EvidenceResults.jsx`: replaces its loose protocol check with the
  shared evidence renderer on every CAPA card. Truly absent evidence keeps its
  existing absent-evidence message; malformed evidence is now visibly invalid.
- `src/frontend/ReadOnlyCapture.jsx`: uses the same renderer and policy. It no
  longer describes a present but invalid URL as absent evidence.
- `src/frontend/DecisionDetails.jsx`: uses the renderer for every stored history
  URL rather than filtering invalid URLs away. Updates the input label to HTTPS
  and stops trimming individual lines before validation. CRLF/LF still delimit
  links; empty lines are ignored, but surrounding spaces and whitespace-only
  entries fail validation instead of being silently repaired.
- `src/frontend/CaptureForm.jsx`: adds HTTPS guidance and the legacy HTTP warning.
  The stored HTTP value still prefills the field unchanged. Its registered
  validator rejects Save until the engineer fixes or deliberately clears the
  optional field; there is no automatic rewrite, deletion or migration.
- `README.md`: documents the new-link and legacy-display policies and edit repair.
- `docs/tasks/T25.md`: implementation and owner handoff.

Tests changed/added:

- `src/lib/__tests__/urls.test.js`: HTTPS acceptance, malformed/credentialed/
  non-HTTPS rejection, whitespace/control characters, missing-host repairs,
  legacy-only HTTP recognition and exact length boundary.
- `src/lib/__tests__/capture.test.js`: capture rejects unsafe URLs without mutation.
- `src/lib/__tests__/decisions.test.js`: HTTPS-only decision validation and message.
- `src/frontend/__tests__/evidenceLink.test.js`: real shared rendering through

- `src/frontend/__tests__/captureForm.test.js`: legacy HTTP remains in the field,
  shows the warning, fails validation and accepts an explicit HTTPS correction.
- `src/resolvers/__tests__/index.test.js`: direct saveCapture of a legacy HTTP
  CAPA edit returns the exact field error without any property write or mutation.
- `src/resolvers/__tests__/decisions.test.js`: direct recordDecision rejects HTTP
  and credentialed URLs without committing a decision.

## Exactly what to click and check

1. On a new CAPA, enter valid quality details including a closed date. In
   **Effectiveness evidence link**, try synthetic `https://user:pass@example.com/x`,
   `http://example.com/report`, `javascript:alert(1)`, and an HTTPS URL with a
   surrounding space. Click **Save** for each: confirm **Use an https:// link.**
   on that field and no successful save. Do not use real credentials for testing.
2. Enter `https://example.com/report`, then **Save**. Confirm success. On a matching
   NC, refresh evidence: **View evidence** is clickable. Validating or rendering
   the link does not fetch its target.
3. On the NC's match card, choose **Engineer-confirmed recurrence**, enter a
   reason and try HTTP, synthetic credentialed HTTPS, and surrounding-space HTTPS
   in **Evidence links**. Click **Record decision**: confirm the HTTPS error.
   Replace with valid HTTPS and record: the history link is clickable.
4. If an existing CAPA has an HTTP link, check its match card and the read-only
   capture view using a non-editor: the original HTTP URL is plain text alongside
   **Not a secure link (http)**. Existing HTTP decision-history links receive the
   same treatment. No HTTP evidence link is clickable.
5. As an editor, open that CAPA's form: the original HTTP value and warning remain.
   Change another field and click **Save**: the evidence field gets the HTTPS
   error. Enter the corrected HTTPS link and save: only that explicit correction
   changes the stored URL. No link was silently dropped or rewritten.
6. For existing malformed/credentialed stored evidence, check the same surfaces:
   **Invalid evidence link** replaces the URL, with no clickable link or echoed
   credentials. These cases are covered by frontend tests if legacy examples are
   unavailable; do not add a debug write path or real credentials to test them.
7. Recheck T23/T24: CAPA date is required, record type remains locked, same-day
   closure is excluded, hyphen spacing still matches strongly, and other
   revisions remain related.
