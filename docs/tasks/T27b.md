# T27b — site-correct NC links and readable confirmations

Read `AGENTS.md`, `docs/tasks/T27.md` and review §1.3. Preserves T23–T27,
including the durable create claim, fresh asUser authorization before writes,
two-link repair, opaque markers and assignee/description rejection handling.

## Files changed and why

- `src/lib/followup.js`: NC browse links now require an explicit Jira site URL.
  Issue `self` is never used. Valid HTTPS site origins are retained; API gateway
  hosts (including trailing-dot forms) are rejected. If no site is available,
  the NC key and summary remain plain text without a link mark. Preview text
  includes the NC link target, binding the displayed URL to confirmation checks.
  Verify confirmation uses newline-joined lines for description, each link,
  marker handling, recording, unchanged assignee and description rejection.
- `src/resolvers/decisions.js`: obtains `serverInfo.baseUrl` with
  `GET /rest/api/3/serverInfo` asUser for creation and repair. Denial, unavailable
  responses, invalid base URLs and transport/JSON failures use the plain-text
  fallback. Neither frontend payloads nor unverified context URL fields supply
  the site. All fresh description comparisons reuse the invocation's site URL;
  a changed site between proposal and confirmation invalidates confirmation.
- `src/lib/decisions.js`: creation confirmation is built from separate lines:
  selected type/project/summary, `Description:`, preview, both links (or explicit
  missing-Relates limits), marker, recording, assignee and description fallback.
  Preview punctuation is preserved without appending a second full stop.
- `src/frontend/DecisionDetails.jsx`: both dialogs split the canonical string
  into one Text per line in a Stack. They send the original newline-joined
  confirmation unchanged; the resolver compares that exact same string.
  Neither dialog uses the term “ADF”.
- `src/lib/__tests__/followup.test.js`: verified description shape with an API
  gateway self URL, site link target preview, plain-text fallback for missing or
  invalid origins, punctuation and separate repair confirmation lines.
- `src/lib/__tests__/decisions.test.js`: exact creation confirmation strings,
  line order, marker and assignee fallback checks.
- `src/resolvers/__tests__/decisions.test.js`: fixtures now use gateway self URLs.
  Tests cover correct serverInfo links, unavailable/invalid site information,
  ignored unverified context fields, changed-site confirmation refusal and both
  linked/plain-text empty-description repairs. Existing claim/no-double-create,
  partial failure, permission, assignee fallback and lockstep tests pass.
- `src/frontend/__tests__/evidenceLoading.test.js`: creation and Verify each
  render individual Text lines whose joined value equals the submitted string.
- `README.md`: documents site-based links and the plain-text fallback.
- `docs/tasks/T27b.md`: verification, checks and owner handoff.

Existing nonempty descriptions, including tasks created before this fix, are
preserved by Verify. Correct an old broken link manually in Jira, or test the
new code with a fresh task or an empty description on a disposable demo task.
