## Result and files

- `src/lib/searchSettings.js`: scopes PROJECT / LISTED / ALL, defaults PROJECT
  and 365 days, supported windows 90/365/730/1095, settings validation, listed-key
  parsing, project membership checks and shared evidence heading text.
- `src/resolvers/searchSettings.js`: installation-scoped KVS
  `settings:<projectId>` holds `{version,scope,lookbackDays,projectIds}`. No
  configuration means local-project/365; malformed settings/storage errors do
  not widen a search. The NC's freshly fetched project determines the key.
  Listed keys are normalized and individually fetched asUser to verify existence
  and browse access, then stored as IDs. Current project is implicit; duplicate
  targets are removed. Input is bounded to 20 additional key entries/2,000 chars.
  Inaccessible/deleted listed projects are omitted from that viewer's search and
  settings display without hidden names, IDs or counts. Local project remains
  included even if none of the listed projects is available. ALL relies on Jira
  asUser access rather than enumerating every project.
  Project browsers can read settings. Writes require ADMINISTER_PROJECTS for
  the exact contextual project before storage access and again before the write.
  A lock/ownership check and expected revision prevent stale-tab overwrites.
  The five-minute lock TTL has Forge's asynchronous deletion behavior; an
  abandoned lock may remain beyond nominal expiry. No unsafe takeover is added.
- `src/resolvers/samples.js`: registers getProjectSearchSettings and
  saveProjectSearchSettings on the existing project-page resolver. No manifest
  module/function change is needed. Existing sample writes/confirmation remain.
- `src/frontend/ProjectSearchSettings.jsx`, `projectPage.jsx`: settings below the
  How to try this walkthrough. Browse-only users see current settings; project
  admins get scope/window selects and an uncontrolled listed-key input with
  latest-value refs. Errors identify unknown/inaccessible keys. Only browseable
  listed keys are displayed, with a notice that saving replaces the list.
  Refresh, pending, permission and stale-save handling reuse safe page-call
  errors; raw bridge transport details are not displayed.
- `src/lib/matchJql.js`, `hintJql.js`: all match/other-related/hint queries take
  the applied window and project IDs. PROJECT/LISTED prepend
  `project in (...) AND ...`, escaping every ID with escapeJqlValue. ALL omits
  the project clause and still searches asUser. An empty explicit scope throws
  rather than accidentally querying all projects. All closure cutoffs remain
  strictly before detection and inclusive at the oldest eligible day.
- `src/lib/match.js`, `hints.js`: apply the same window and optional project
  restriction in memory. Eligible closure dates are 1..lookbackDays days before
  detection. Hint exclusion/reasons use that window, including the outside-N-day
  wording; older precedents remain hints rather than matches. Pure-function
  defaults remain 365 with no project filter for the existing evaluation.
- `src/resolvers/evidence.js`: one current-issue GET retrieves the NC property
  and actual project together. Search and direct candidate reads request project
  metadata; classification checks the scope/window on both snapshots and fresh
  reads, including CAPAs moved out of scope. Returns public scope/window metadata
  without the internal project-ID list. Existing caps, budgets, direct browse
  checks and hidden-record omission remain.
- `src/resolvers/index.js`: hint searches use the NC project's settings and
  fresh candidate project metadata; budget-limited hints never use a wider
  fallback scope. Capture/catalogue/type/URL handling remains unchanged.
- `src/resolvers/decisions.js`: eligibility recheck also loads the NC project
  settings. A visible 400-day match at 730 days can receive a decision; an
  out-of-window/out-of-scope CAPA cannot bypass matching via direct invoke.
  Versioned decision transactions, claim/recovery and follow-up behavior remain.
- `src/frontend/EvidenceResults.jsx`, `HintResults.jsx`: shared panel/side-view
  heading shows `Searching <scope> · CAPAs closed 1–<N> days before detection`.
  No-match copy and hints use N. PROJECT-only results with no strong/revision
  match show the exact requested one-line widening guidance. Existing history
  remains subject to browse authorization even when outside current search scope.
- `README.md`: controls, defaults, permissions, migration/retention limits and
  the fixed eval default. Project settings are metadata; existing Data health
  cleanup does not remove these KVS keys when a project is deleted. No new cleanup
  job or Jira issue write is introduced.
- New tests: `src/lib/__tests__/searchSettings.test.js`,
  `src/resolvers/__tests__/searchSettings.test.js`,
  `src/frontend/__tests__/projectSearchSettings.test.js`.
- Updated tests: resolver `index.test.js`, `decisions.test.js`,
  `scale.simulated.test.js`, `loadSpeed.simulated.test.js`; frontend
  `projectPage.test.js`, `evidenceLoading.test.js`, `hintResults.test.js`.
  Fixtures now model actual project metadata and the combined NC read. Simulated
  Jira counts remain unchanged; the load-speed model counts one additional KVS
  settings read (storageGet 4 instead of 3 for the modeled load).
- `docs/tasks/T30.md`: this new record and owner handoff.
