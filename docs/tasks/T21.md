# T21 — Re-audit 2 fixes: N-01, N-02, N-03, N-05

Implemented fresh cross-query classification, create-time opaque task markers with durable recovery, and separate disclosure of unchecked candidates and verified omissions. No new scopes. The hidden `eval/test/` split was not opened or modified.

## Files changed and why

- `src/resolvers/evidence.js`: classify each completed direct `asUser()` read into `strong`, `relatedRevision`, or `otherRelated`, regardless of the discovering query. Snapshot candidates may qualify for any class as well. Keep the newest 25 verified matches per signature class, ordered by closure descending and key ascending. Count displaced verified matches in `verifiedNotShown`, remove them from the authorised cache, and exclude them from historical-pair loading through `undisplayed`. Keep `notShown` exclusively for unread signature candidates. Either kind of omission sets the existing completeness guard `uncheckedCandidates`, preventing definitive no-match wording. Search caps, permission handling, the shared time budget, and five-read concurrency remain in place; every displayed record requires a completed direct read.
- `src/frontend/EvidenceResults.jsx`: retain the existing `N more candidates not checked` line and show a separate `N more verified matches not shown (most recent 25 shown)` line for each affected signature class.
- `src/resolvers/decisionStore.js`: generate a random 128-bit marker token with `node:crypto.randomBytes(16).toString('hex')`. Persist `taskMarkerVersion: 2` and `taskMarkerToken` in the same durable conditional claim before a create-issue request can run.
- `src/lib/followup.js`: construct v2 properties containing exactly `{ schemaVersion: 2, token }`. Require the exact stored token for v2 recovery; missing, malformed, conflicting, or v1 properties cannot recover a v2 claim. Preserve exact-ID-and-claim-time validation for existing v1 markers and the warning/confirmation path for pre-marker legacy claims. The friendly creation confirmation sentence needs no change.
- `src/resolvers/decisions.js`: include the marker in the create request's top-level `properties` array, including the definitive assignee-rejection retry. Preserve saving the returned key, the post-create `asUser()` task/CAPA checks, linking, and separate `taskLinkedAt` recording. The task read now includes its marker; only a verified absence permits a fallback property PUT. A present conflicting property is never overwritten or linked. Link repair supports missing v2 markers under its existing explicit confirmation.
- `manifest.yml`: add the optional string attribute `taskMarkerToken` to the `decision` custom entity.
- `src/resolvers/__tests__/scale.simulated.test.js`: cover other-related-to-signature moves, signature-to-other-related moves, full destination classes, newest-25 retention, separate unread/verified counts, verified-only completeness guards, cache exclusion, and direct-read reuse.
- `src/resolvers/__tests__/index.test.js`: update the expected resolver response for the new verified-omission counters.
- `src/resolvers/__tests__/decisionStore.test.js`: verify new claims durably store v2, a 32-character random hex token, and the claim time; separate claims get different tokens.
- `src/resolvers/__tests__/decisions.test.js`: model Jira's create-time properties; verify create payload and call ordering, lost-create-response recovery with no saved key, exact-token rejection/rechecks, fallback only after a read finds no property, conflicting-property refusal, and retained v1/legacy recovery and link behavior.
- `src/lib/__tests__/followup.test.js`: verify the opaque property's exact two-key shape, stored-token validation, malformed/missing-token rejection, and v1 compatibility.
- `src/frontend/__tests__/evidenceLoading.test.js`: verify separate omission lines and suppression of definitive no-match wording, including verified omissions without unread candidates.
- `docs/tasks/T21.md`: record implementation, verification, manifest changes, and owner checks.
