# T17 — Follow-up dialog wording

Updated the follow-up confirmation text to match the CAPA's ownership:

- No assignee: ends with `Assignee: none (the CAPA has no assignee).` and omits the Jira rejection sentence.
- Assignee present: ends with `Intended assignee: <displayName>. If Jira rejects this assignee, the task is created unassigned.` Display names are trimmed; the existing `the CAPA's current assignee` label remains when a display name is unavailable. Account IDs are never included in the confirmation.

## Files changed

- `src/lib/decisions.js`: select the ownership wording in `followupConfirmation`. Assignment detection, task creation, ownership rechecks and assignment rejection fallback retain their existing behavior.
- `src/lib/__tests__/decisions.test.js`: separate exact-text tests for unassigned and assigned CAPAs, including omitted fallback text, trimmed display names and account ID privacy.
- `src/lib/__tests__/followup.test.js`: cover absent/null/empty assignees and assigned confirmations, preserve missing-display-name privacy coverage, and retain the recovery confirmation assertion.
- `src/resolvers/__tests__/decisions.test.js`: assert the literal unassigned proposal and complete assigned proposal wording. Existing creation tests still verify the account ID is sent to Jira, unassigned creation uses null, and definitive assignee rejection retries unassigned.
- `docs/tasks/T17.md`: record the change, validation and owner checks.

## Owner click/check walkthrough

1. Use an editable NC with a matching, visible CAPA that has no assignee and no effectiveness evidence (or an engineer-confirmed recurrence), in a project where you can create tasks.
2. Open **QualityLoop**, click **Refresh evidence and decisions**, and select **Effectiveness concern** on that CAPA. Enter a reason and click **Record decision**.
3. In **Confirm follow-up task**, check the project, task title and CAPA link. Verify the text ends exactly with **Assignee: none (the CAPA has no assignee).** and contains no **If Jira rejects** sentence. Click **Keep decision only** to inspect the wording without creating a task.
4. Repeat with an assigned CAPA. Verify **Intended assignee: <displayName>. If Jira rejects this assignee, the task is created unassigned.** and no account ID. Click **Keep decision only** to close the dialog.
5. To check creation in the development project, repeat each case and click **Create task and link**. Open the resulting task: verify its project, title and link to the CAPA, and that its assignee is absent or matches the CAPA owner respectively. Where Jira rejects the intended assignee but permits unassigned tasks, the existing fallback should still create the task unassigned; the automated resolver test covers this rejection deterministically.
