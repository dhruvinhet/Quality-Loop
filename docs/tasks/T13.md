Audit coverage: QL-09, QL-10 and QL-12. Checked on 2026-11-02 with Node.js v24.22.2 and npm 11.19.1 on Windows. No application source, scripts, dependency declarations (other than the package name), or manifest entries were changed.

## Lockfile failure and repair

After deleting the repository's `node_modules`, plain `npm ci` reproduced the original error:

```text
npm error code EUSAGE
npm error Missing: react-dom@18.3.1 from lock file
```

The version-2 lockfile already locked React 18.3.1 and 16 packages declaring React DOM peer dependencies, including `@atlaskit/analytics-next` (`react-dom: ^18.2.0`). It omitted React DOM from both `packages` and the version-2 compatibility `dependencies` map. Default npm peer resolution therefore required React DOM 18.3.1, compatible with the locked React version, but `npm ci` requires a complete lockfile and cannot repair it.

The repository previously documented `npm ci --legacy-peer-deps` in [T4](T4.md). That skips peer resolution and is consistent with the incomplete lockfile; the exact historical command that generated the old file cannot be established from this checkout. The concrete cause is the missing required peer in the lockfile, rather than a missing direct dependency declaration in `package.json`.

Regenerated with `node_modules` absent, retaining the existing lockfile as the resolution baseline:

```powershell
npm install --package-lock-only --lockfile-version=2 --ignore-scripts --no-audit --no-fund
```

The regenerated lockfile preserves all 817 existing package entries and their versions, including all three prerelease pins and React 18.3.1. Its only new package is the peer `react-dom@18.3.1`; its `loose-envify` and `scheduler` dependencies were already locked. npm also writes empty `requires` objects for 13 existing entries in the version-2 compatibility map. The top-level and root-package lockfile names follow the renamed package. No direct React DOM dependency, legacy-peer setting, or `.npmrc` workaround was added.

Plain `npm ci` then succeeded with no `node_modules` present. The command did not change the repaired lockfile. Existing React-16 peer warnings and deprecation warnings remain. The install reports 39 vulnerabilities (1 low, 25 moderate, 13 high); no audit fixes or dependency upgrades were applied. npm 11.19.1 also reports four packages whose install scripts are not covered by its allowScripts policy; all requested checks nevertheless pass.
