## Limits and migration

CAPAs saved under a different preset (another project, or before a preset change) may be missed as related revisions until re-saved or re-indexed. Maintenance recomputes each record using its own project's current preset, so cross-project preset differences can still prevent related retrieval after maintenance. Exact retrieval uses qlPart independently of the stored base/preset. Legacy stale whole-part values can still miss exact JQL until refreshed; fetched records are always re-normalised from partOriginal.

Maintenance covers Jira-indexed NC/CAPA properties and proceeds one ten-issue page at a time. Jira indexes update asynchronously. Reopen capture panels after changing project settings to refresh the preview; the server always saves with the current preset. As with existing Jira property saves, the fresh read/fingerprint check and PUT are separate REST calls; Jira does not offer a conditional version parameter on the verified property PUT. A concurrent external edit in that small interval is not atomically excluded.
