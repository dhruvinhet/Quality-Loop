## Files changed and resulting behavior

- `src/lib/capture.js`: CAPA save validation requires `closedDate`, with the exact
  review message: “Select a closed date for a CAPA. Matching uses this date, not Jira status.”
  This validation is shared by client and server and applies to new save attempts,
  including attempts to save edits to a legacy CAPA. Loading old records does not
  run save validation or migrate their data.
- `src/frontend/CaptureForm.jsx`: shows `Closed date *` and “Required for recurrence
  matching. Jira status is not used.” Disables record type whenever a saved
  `record.recordType` exists, including immediately after the parent receives the
  first successful save. Keeps the selected type in form registration/submission.
- `src/resolvers/index.js`: reads the context issue and its `qualityloop` property
  as the viewing user before save validation. Rejects a stored record-type change
  with “Record type cannot be changed after the first save. Create a new issue instead.”
  Checking type first guarantees this exact error even when the attempted conversion
  also omits CAPA-required fields. A direct issue GET distinguishes an accessible
  issue without a property from an inaccessible issue; property GET alone returns
  404 for both. Denied/missing issues return null, and failed reads never write.
  The current-issue property PUT still runs asUser and handles revoked access.
- `src/lib/matchJql.js`: the shared bounded JQL now uses `qlClosed < detectedDate`,
  including other-related searches. The pure matcher is unchanged.
- `src/lib/__tests__/capture.test.js`: covers required/malformed CAPA closed dates
  and updates valid CAPA fixtures. NC validation remains unchanged.
- `src/lib/__tests__/match.test.js`: updates the exact JQL expectation. Existing
  0/1/365/366-day matcher tests still pass.
- `src/resolvers/__tests__/index.test.js`: covers direct NC→CAPA and CAPA→NC
  conversion rejection, rejection precedence, same-type edits, missing-date
  rejection, legacy schema 1/2 loads and subsequent date repair, inaccessible
  reads, read failures, and revoked write access.
- `src/frontend/__tests__/captureForm.test.js`: covers the required marker and
  hint, registered client validator, NC field visibility, saved-type lock,
  submitting lock, legacy blank-date rendering, and retained submission values.
- `docs/tasks/T23.md`: implementation, verification, and owner handoff.

Legacy no-date hint selection/search remains unchanged. Existing resolver and hint
unit tests still verify that exact-part legacy CAPAs appear as “No closed date
recorded”, with no promotion to a match. Existing Jira-status consistency warning
tests also pass. No stored CAPA data, decisions, statuses, or matching rules changed.
