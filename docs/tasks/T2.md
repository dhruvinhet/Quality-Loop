# T2 owner runbook

QualityLoop finds possible recurrence evidence on panel load and after saving.
The **QualityLoop evidence** issue-context panel shows the same accessible results
without a capture form or buttons. Both views use `findMatches`. No decisions,
Forge storage, triggers, AI calls, or external fetches are implemented.

## Commands and manifest

Use Node.js 22.x or 24.x in this directory. No dependencies changed. Run in order;
only the owner runs deployment and installation:

```powershell
npm test
npm run lint
npm run build
forge lint
forge deploy
forge install --upgrade
```

Use the intended environment and existing Jira installation when prompted. Build
before deployment: the shared clipboard Frame needs its generated resource.

The manifest adds `jira:issueContext` with title and label **QualityLoop evidence**,
`render: native`, the existing resolver, and a new `evidence-context` resource.
`app.id`, runtime, indexes, and scopes are unchanged. No new scopes are needed:

- `read:jira-work`: current property GET, enhanced JQL search, candidate issue GET
  including properties; also required by the entity-property-set module.
- `write:jira-work`: existing capture PUT and deliberately enabled E1 probe PUT
  on the current issue; also required by the property-set module.

Any future scope change needs owner `forge deploy`, then `forge install --upgrade`.

## Rules and data

Capture writes schema version 2; version-1 captures still load and match. Optional
CAPA-only **Root cause** and **Actions taken** fields accept up to 2,000 characters
each and are not indexed. Missing narratives display **not recorded**. Saving an
NC clears all CAPA-only fields. Original part strings remain intact.

The default window is 365 days in `src/config/matching.js`. Both date bounds are
inclusive and calculated as UTC calendar days. The recorded closed date defines
closure; Jira status is displayed and never changed.

| Class | Rule within the window |
| --- | --- |
| strong | Equal normalized part and equal failure-mode code |
| relatedRevision | Equal base, different revision, equal failure mode; never strong |
| otherRelated | Equal normalized part and different failure mode, or equal failure mode and supplier with a different base |

The current issue, non-CAPAs, missing/invalid closed dates, future closures, and
out-of-window closures are excluded. Same supplier and same line are listed when
nonempty and exactly equal; they are facts, never scores. Strong cards precede
related-revision cards; each class sorts by closure descending, then key ascending.
Other related records are collapsed by default in the issue panel. The button-free
issue-context view lists them directly under their count.

Normalization trims, collapses whitespace, and uppercases; it does not remove
punctuation or correct typos. Revision parsing uses `src/config/partPattern.js`.
For example, `" p-4471 -a "` has base `"P-4471 "`, including the trailing space,
different from `"P-4471"`. Schema-v1 missing narratives render as not recorded.

## Search and permissions

`findMatches` accepts no payload fields. Its issue ID comes exclusively from
`req.context.extension.issue.id`. It reads the current property `asUser()` and
returns `{applicable:false}` for non-NCs or missing/invalid detected dates.
Missing/inaccessible current properties return no data.

Search uses `POST /rest/api/3/search/jql`, 50 results per page,
`fields: ['summary', 'status']`, and `properties: ['qualityloop']`. It follows
`nextPageToken` instead of returning partial results. Example query:

```text
qlRecordType = "CAPA" AND (qlPartBase = "P-4471" OR qlFailureMode = "FM-01") AND qlClosed <= "2026-10-31" AND qlClosed >= "2025-10-31" ORDER BY qlClosed DESC, key ASC
```

Every candidate is re-fetched `asUser()` for fresh summary, status and property.
Search snapshots are never returned as evidence. A 403/404 silently drops the
candidate, without a hidden count; other API errors return an error instead of an
incomplete no-match result. Re-fetches run in groups of five. Large result sets
can encounter Forge's resolver time limit and need live testing.

E1 observed indexing visibility 2.1–3.4 seconds after writes. The NC is read
directly after Save, so NC indexing does not delay matching. Newly saved CAPAs
may need several seconds before search finds them; reopen the NC panel afterward.
No background retries or monitoring run. All capture writes target the current issue.

## Dev checks

Both `E1_PROBE` and new `E2_CHECK` default to false in `src/config/devFlags.js`.
The E1 code and backend flag gates are retained.

With only `E2_CHECK = true`, build/deploy and open a saved NC. **Run match 20x**
performs twenty sequential frontend calls to the same `findMatches` resolver.
Equality compares all evidence, excluding only `elapsedMs`. It reports equality
and min/median/max resolver milliseconds. **Copy results** copies full JSON,
including every result body and timing. Closing the panel stops further calls;
errors cannot count as identical results. The existing Forge-hosted clipboard
Frame provides copying and a selected-text fallback if clipboard access is denied.
Use one dev check at a time. Disable the flag and build/deploy after testing.

## Owner click/check sequence

1. On separate browsable test issues, open **qualityloop** from the issue Apps
   menu and save CAPAs below. Set supplier `Supplier T2` and line `Line 1` on each.
   On the first CAPA enter root cause `Fixture wear`, actions `Replaced fixture`,
   and a valid HTTP(S) evidence link. Leave these fields empty on the revision CAPA.

   | Part | Failure mode | Closed date | Expected |
   | --- | --- | --- | --- |
   | `P-4471-A` | FM-01 Crack | 2026-10-01 | strong, 30 days |
   | `P-4471-B` | FM-01 Crack | 2026-10-02 | related revision B |
   | `P-4471-A` | FM-02 Dimension out of tolerance | 2026-10-03 | other related |
   | `P-9999-A` | FM-01 Crack | 2026-10-04 | other related |
   | `P-4471-A` | FM-01 Crack | 2026-11-01 | excluded: after detection |
   | `P-4471-A` | FM-01 Crack | 2025-10-30 | excluded: outside window |
   | `P-4471-A` | FM-01 Crack | blank | excluded: no closure |

2. Wait five seconds after CAPA saves. On another issue save an NC with part
   ` p-4471-a `, FM-01 Crack, supplier `Supplier T2`, line `Line 1`, detected date
   `2026-10-31`. Confirm results refresh after Save. Check linked key and summary,
   original part, code/name, 30-day interval, dates/status, supplier/line facts,
   narratives, evidence link, and missing-evidence wording. Revision B must be
   related and never strong. **Other related records (2)** must start collapsed;
   expand it and check the expected two records. The remaining CAPAs are absent.
3. Add equal-closure-date CAPAs to check key ordering. Reload/reopen the NC panel
   to check load-time matching. Change the NC to an unmatched part/failure mode
   and Save; check the 365-day empty state. Switch to CAPA and Save; NC evidence
   must disappear. Narrative inputs appear only for CAPA. Load a pre-T2 version-1
   capture, confirm prefill, then Save to upgrade it to schema 2.
4. Restore the NC fixture. Expand **QualityLoop evidence** in Jira's right-hand
   issue-context area. Check the same records/evidence with no form or buttons.
   Other related records are a plain list there. Reopen/reload after saving in
   the separate issue panel. A browse-only viewer can use the context view.
5. Use a viewer who can browse the NC but not one candidate. Reopen both views;
   that candidate's key, summary, evidence and count must be absent. If supported,
   revoke candidate access between search and re-fetch and check again.
6. Save another CAPA/NC pair with part `P-"4471\X-A`, equal failure mode, and valid
   dates. Wait for indexing and check a strong result. In advanced Jira search
   the escaped base literal is `qlPartBase = "P-\"4471\\X"`. Also run the date-window
   query above to check alias/date behavior on your site.
7. Enable only E2, build/deploy, click **Run match 20x**, and confirm 20 identical
   results on unchanged fixtures and timing statistics. Click **Copy results**,
   paste into a text editor, and verify all 20 bodies and timings. Check manual
   copy if clipboard access is denied. Disable E2, build/deploy, and confirm both
   dev controls are absent.
