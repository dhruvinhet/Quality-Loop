## Migration and limits

JQL on supplierNorm covers only CAPAs saved after this change. In-memory
comparisons can handle old records once fetched, but cannot make absent indexed
fields searchable. Re-save affected CAPAs to populate v3 norms. No automated
backfill or background job is added. The evidence view discloses this even for
a v3 NC, because its candidate CAPAs may still be old. The known old partBase
limitation remains. Old noncanonical failure codes written directly into Jira
can also be missed by canonical JQL until re-saved.

Deactivated codes still match in existing NC/CAPA records; they are excluded from
new saves, not erased from history. Labels are current site metadata rather than
historical snapshots. A label rename does not rewrite captures or alter matching.
Open forms must reload after admin changes; a concurrent deactivation causes
server validation to reject the stale selection. A custom code still creates a
strong match on matching part/date fields, including across projects where the
viewer can browse both issues.
