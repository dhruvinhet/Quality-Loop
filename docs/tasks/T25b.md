  decisions consume the reason directly. Existing strict validation and the

  | Problem | Message |
  | --- | --- |
  | Credentials | Remove the user name and password from the link. |
  | Surrounding spaces | Remove spaces before or after the link. |
  | HTTP or another explicit scheme | Use an https:// link. |
  | Otherwise malformed, control characters, missing host, wrong type or excessive length | Enter a full https:// link. |

- `src/lib/capture.js`, `src/lib/decisions.js`: use the shared reason for URL

- `src/frontend/EvidenceLink.jsx`: upgrades legacy HTTP's note to
  `SectionMessage appearance="warning"`; HTTP stays plain text and all invalid

## Verified UI Kit limitation and implementation choice

The requested `mode: 'onSubmit'` and `reValidateMode: 'onSubmit'` settings **cannot
be configured through the installed Forge UI Kit 12.4.0 `useForm`**:

- Forge MCP `search-forge-docs` returned the [useForm reference](https://developer.atlassian.com/platform/forge/ui-kit/hooks/use-form/),
  whose only documented input option is `defaultValues`.
- Installed `node_modules/@forge/react/out/hooks/useForm.d.ts` accepts only
  `Pick<UseFormProps, 'defaultValues'>`.
- Installed `node_modules/@forge/react/out/hooks/useForm.js` forwards only
  `defaultValues` and hardcodes `mode: 'onBlur'`, `reValidateMode: 'onChange'`.
  Its change handler can trigger validation after touch/submit, and its blur
  handler triggers validation directly. Merely passing the requested options
  would be ignored.

The implementation therefore uses the documented submission-validation path:
register inputs without validation rules, call the shared `validateCapture()`
inside the submit callback, and keep errors in component state until the next
submit. This achieves the requested submit-only behavior without unsupported
options, dependency changes or patching UI Kit. The documented `handleSubmit`
error callback also clears the banner if the hook rejects a submission.

Forge MCP `get-ui-kit-component-reference`, using the unchanged manifest app ID,
verified props for TextArea, SectionMessage and the form/input/layout/modal
components used here. In particular, TextArea supports `defaultValue`/`onChange`,
and SectionMessage supports both `error` and `warning` appearances. Sources:
[TextArea](https://developer.atlassian.com/platform/forge/ui-kit/components/text-area/),
[SectionMessage](https://developer.atlassian.com/platform/forge/ui-kit/components/section-message/),
[Form](https://developer.atlassian.com/platform/forge/ui-kit/components/form/).

Nothing implemented relies on an unverified UI Kit prop. The literal mode
settings remain unsupported; live bridge timing and rendering remain owner
checks. No Jira REST calls were added or changed.

## Exactly what to click and check live

1. On a matched NC, open **Engineer-confirmed recurrence**. Type **Different weld
   cell** quickly; paste two valid HTTPS URLs on separate lines. Record the
   decision. Confirm history contains the full reason and both complete URLs.
   Repeat with a pasted reason and with **Not a recurrence** plus a category.
2. In the decision dialog, try synthetic credentials, surrounding spaces, HTTP,
   and a malformed URL. Confirm each specific message above appears in a red
   error SectionMessage. If a server error occurs, confirm it has the same styling.
3. On a CAPA, save valid details to display success. Edit any field: the success
   message must disappear. Enter a bad evidence URL and click **Save**: confirm
   the specific field error and no stale success message.
4. Correct the URL, then click **Save** directly from the field. The error must
   stay in place through editing and blur, and this first click must submit and
   save. Confirm the error disappears only on submit, and success follows the
   completed save. Repeat after clicking elsewhere to blur before Save.
5. Check the evidence helper reads **Optional. Must start with https://**.
   Existing HTTP evidence must have a visible warning-styled **Not a secure link
   (http)** note in the capture form, match cards, read-only capture, and history.
   HTTP remains plain text; invalid URLs remain **Invalid evidence link**.
6. Confirm T23's required CAPA date, saved-type lock and strict closure window,
   and T24's strong hyphen-spacing matches / related revisions still work.
   Review on GitHub and complete live checks before proceeding to the next task.
